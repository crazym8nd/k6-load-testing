# k6-load-testing

Навык нагрузочного тестирования сервиса через k6 (Docker): полный цикл — стенд с прод-конфигурацией, seed, smoke, 4 типа тестов, анализ и отчёт.

## Что делает

- Воспроизводит **прод-конфигурацию** (CPU/RAM/heap/пул БД) и **прод-объёмы данных** в локальном Docker-стенде — не гоняет на дефолтах.
- Гоняет **4 типа тестов**:
  - **baseline** — RPS / p95 / ошибки на заданной нагрузке;
  - **stress** — «колено» (потолок) ступенчатым ростом RPS;
  - **spike** — выживание при всплеске + восстановление;
  - **soak** — утечки за часы (запускается пользователем, не агентом).
- Читает **метрики приложения** (Prometheus/Actuator) параллельно с k6 — CPU, heap, GC, пул соединений — чтобы ответить «почему медленно», а не только «что медленно».
- Даёт **отчёт одной нитью** (verdict → результаты → выводы по severity → рекомендации → бизнес-резюме).

## Структура

| Путь | Назначение |
|---|---|
| `SKILL.md` | ядро: флоу (11 шагов), правила, частые ошибки |
| `references/` | детали: типы тестов, анализ, executors, паттерны узких мест, seed, стенд |
| `template/scripts/` | k6-инструментарий: сценарии + lib |
| `template/soak-run.sh` | скрипт soak (ручной запуск) |
| `examples/report-example.md` | эталон формата отчёта |

## Быстрый старт

1. Полный флоу — в `SKILL.md`.
2. Скопировать `template/scripts` в `.tmp/loadtest/scripts`.
3. Заполнить `services/<service>/endpoints.js` и `lib/services.js`.
4. Smoke → выбранный тип теста:
   ```bash
   docker run --rm -u "$(id -u):$(id -g)" -v "$PWD":/k6 -w /k6 \
     grafana/k6:0.57.0 run -e SERVICE=<service> -e BASE_URL=<url> scripts/<scenario>.js
   ```

## Требования

- Docker (стенд + k6).
- k6-образ `grafana/k6:0.57.0` (тянется автоматически).
- bash — для `soak-run.sh` (Windows: Git Bash / WSL).
